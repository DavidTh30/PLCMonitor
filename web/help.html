Getting startedเริ่มต้นใช้งาน

PLC Monitor reads values from ISO-TCP PLCs and Modbus devices, shows them live, charts them, and passes every change on to a CSV file, InfluxDB and/or an MQTT broker.

PLC Monitor อ่านค่าจาก PLC แบบ ISO-TCP และอุปกรณ์ Modbus แสดงค่าแบบ real-time วาดกราฟ และส่งทุกค่าที่เปลี่ยนไปยังไฟล์ CSV, InfluxDB และ/หรือ MQTT broker

  1. File → Network settings (or the Network settings button): choose ISO-TCP or Modbus and enter the address. Tick Use the built-in simulator to try everything without a device.
  2. + Add tag: enter where the value is (area, offset, type). Values appear in the table at the next poll.
  3. Chart on a row shows the trend; Write sends a value or runs a signal generator.
  4. Export (button at the top, or File → Export → Export settings): send changes to CSV, InfluxDB or MQTT. Each has a Test connection button.
  5. File → Save keeps the network and tag settings in files you can open again later.
  1. File → Network settings (หรือปุ่ม Network settings): เลือก ISO-TCP หรือ Modbus แล้วใส่ address ติ๊ก Use the built-in simulator เพื่อลองใช้งานโดยไม่ต้องมีอุปกรณ์จริง
  2. + Add tag: ใส่ตำแหน่งของค่า (area, offset, type) ค่าจะขึ้นในตารางในรอบอ่านถัดไป
  3. ปุ่ม Chart ในแต่ละแถวแสดงกราฟ ปุ่ม Write เขียนค่าหรือเปิด signal generator
  4. Export (ปุ่มด้านบน หรือ File → Export → Export settings): ส่งค่าที่เปลี่ยนไป CSV, InfluxDB หรือ MQTT ทุกแบบมีปุ่ม Test connection สำหรับทดสอบ
  5. File → Save บันทึกการตั้งค่า network และ tag เป็นไฟล์ เพื่อเปิดใช้ภายหลัง

Modbus Reading Modbus devicesอ่านค่าจากอุปกรณ์ Modbus

Modbus is the common language of energy meters, inverters, drives, temperature controllers and many PLCs. PLC Monitor is the master (client): it asks, the devices (slaves) answer. Choose the connection in Network settings → Protocol:

Modbus เป็นภาษากลางของมิเตอร์ไฟฟ้า อินเวอร์เตอร์ ไดรฟ์ ตัวควบคุมอุณหภูมิ และ PLC หลายรุ่น PLC Monitor เป็น master (client) ที่ถามค่า ส่วนอุปกรณ์ (slave) เป็นฝ่ายตอบ เลือกรูปแบบการเชื่อมต่อได้ที่ Network settings → Protocol:

Modbus TCP

  1. Make sure the PC and the device are in the same network: e.g. PC 192.168.1.5, device 192.168.1.20, mask 255.255.255.0. ping 192.168.1.20 should answer.
  2. Network settings → Protocol Modbus TCP/IP → Device address 192.168.1.20 (port 502 is added automatically) → Default unit ID from the device manual (often 1; some PLCs use 255).
  3. Press Apply & reconnect. The top bar turns green CONNECTED once a tag reads successfully.
  4. Not sure of the IP? Open Topology and press Scan: it lists every device answering on port 502.
  1. ให้ PC กับอุปกรณ์อยู่ในวง network เดียวกัน เช่น PC 192.168.1.5 อุปกรณ์ 192.168.1.20 mask 255.255.255.0 แล้วลอง ping 192.168.1.20 ต้องมีการตอบกลับ
  2. Network settings → Protocol Modbus TCP/IP → Device address 192.168.1.20 (ไม่ต้องใส่พอร์ต 502 โปรแกรมเติมให้) → Default unit ID ตามคู่มืออุปกรณ์ (ส่วนใหญ่เป็น 1 บาง PLC ใช้ 255)
  3. กด Apply & reconnect แถบด้านบนจะเป็นสีเขียว CONNECTED เมื่ออ่าน tag ได้สำเร็จ
  4. ไม่รู้ IP ของอุปกรณ์? เปิดหน้า Topology แล้วกด Scan จะแสดงทุกอุปกรณ์ที่ตอบบนพอร์ต 502

Modbus RTU – RS485

  1. Plug in the USB-RS485 adapter (install its driver). Windows Device Manager shows it under Ports (COM & LPT), e.g. COM3.
  2. On every device set a different slave ID and the same baud rate, data bits, parity and stop bits (commonly 9600 8N1 or 9600 8E1).
  3. Network settings → Protocol Modbus RTU – RS485 / RS232 (COM port) → pick the serial port (press ↻ after plugging in) → baud rate, parity … → Default unit ID = the ID most tags use.
  4. Tags of other devices: set their Slave ID in the tag dialog. The address column then shows e.g. U2:HR100.
  5. Set the timeout to about 300–500 ms: a device that is switched off then only slows the poll down a little.
  6. Which IDs are on the cable? Topology → Scan slave IDs asks every ID on the current connection.
  1. เสียบตัวแปลง USB-RS485 (ติดตั้งไดรเวอร์ให้เรียบร้อย) ใน Device Manager ของ Windows จะเห็นอยู่ใต้ Ports (COM & LPT) เช่น COM3
  2. ตั้ง slave ID ไม่ซ้ำกัน ในทุกอุปกรณ์ และตั้ง baud rate, data bits, parity, stop bits ให้เหมือนกัน (ที่ใช้บ่อยคือ 9600 8N1 หรือ 9600 8E1)
  3. Network settings → Protocol Modbus RTU – RS485 / RS232 (COM port) → เลือก serial port (เสียบสายแล้วกด ↻) → baud rate, parity … → Default unit ID = ID ที่ tag ส่วนใหญ่ใช้
  4. tag ของอุปกรณ์ตัวอื่น ให้ใส่ Slave ID ในหน้าต่าง tag คอลัมน์ Address จะแสดงเป็น เช่น U2:HR100
  5. ตั้ง timeout ประมาณ 300–500 ms ถ้ามีอุปกรณ์ปิดอยู่ รอบการอ่านจะช้าลงเพียงเล็กน้อย
  6. อยากรู้ว่ามี ID อะไรอยู่บนสายบ้าง? ใช้ Topology → Scan slave IDs โปรแกรมจะถามทีละ ID ผ่านการเชื่อมต่อปัจจุบัน

Device manuals list registers in one of two styles. PLC Monitor uses the 0-based offset of each area:

คู่มืออุปกรณ์เขียนเลข register ได้สองแบบ PLC Monitor ใช้ offset ที่เริ่มนับจาก 0 ของแต่ละ area:

HR holding registerssettings, values (16-bit)ค่าตั้ง ค่าวัด (16 บิต)40001 / 400001 / 0x00000✔
IR input registersmeasurements (16-bit)ค่าวัด (16 บิต)30001 / 3000010–
COIL coilson/off outputsเอาต์พุต เปิด/ปิด000010✔

Rule: offset = register number − first number. Register 40101 → HR offset 100; 30001 → IR offset 0. If the manual already counts from 0 (hex addresses such as 0x0064), use that number as the offset.

วิธีคิด: offset = เลข register − เลขตัวแรก เช่น register 40101 → HR offset 100, 30001 → IR offset 0 ถ้าคู่มือนับจาก 0 อยู่แล้ว (เช่นเลขฐานสิบหก 0x0064) ให้ใช้เลขนั้นเป็น offset ได้เลย

32-bit values (REAL/float, DINT, DWORD) use two registers. Devices differ in which register comes first; if a value looks absurd (e.g. 1.4E-41 instead of 230.5), switch Network settings → 32/64-bit word order:

ค่า 32 บิต (REAL/float, DINT, DWORD) ใช้ 2 register แต่ละยี่ห้อเรียงลำดับไม่เหมือนกัน ถ้าค่าที่อ่านได้แปลก ๆ (เช่น 1.4E-41 แทนที่จะเป็น 230.5) ให้สลับ Network settings → 32/64-bit word order:

Tag names from the PLCดึงชื่อ Tag จาก PLC

ISO-TCP (PUT/GET, port 102) only moves bytes: the PLC never sends the names you gave your tags in the PLC engineering software. Names come either from the PLC's OPC UA server, which publishes every variable by its symbolic name, or from files exported from the engineering software.

ISO-TCP (PUT/GET, port 102) ส่งมาแค่ค่า byte PLC ไม่ส่งชื่อ Tag ที่ตั้งไว้ในโปรแกรมเขียน PLC (engineering software) มาด้วย ชื่อจึงต้องมาจาก OPC UA server ของ PLC ซึ่งเปิดเผยตัวแปรทุกตัวตามชื่อ หรือจากไฟล์ที่ export จากโปรแกรมเขียน PLC

Switch on OPC UA in the PLC engineering softwareเปิด OPC UA ในโปรแกรมเขียน PLC (engineering software)

  1. CPU properties → OPC UA → Server → General: tick Activate OPC UA server. Note the server address (port 4840). Also tick Enable standard server interface (1200-series CPUs from firmware 4.5 and 1500-series CPUs from 2.9, under Server interfaces): without it the PLC answers but publishes no tags, and the PLC tags window says so.
  2. Runtime licenses → OPC UA: choose the OPC UA runtime licence that fits the CPU (small/medium/large for 1500-series, Basic for 1200-series).
  3. Server → Security: for a first test allow No security and Guest authentication. With security on, choose Sign & encrypt / Basic256Sha256 in PLC Monitor and trust its certificate (opcua-client-cert.pem next to the config), or tick Automatically accept client certificates during runtime.
  4. For each data block and PLC tag: Accessible from HMI/OPC UA and Visible in HMI engineering must be ticked (they are by default). With the standard server interface, all such variables are published.
  5. Download to the CPU. In PLC Monitor: Tools → PLC tags (OPC UA) → endpoint opc.tcp://<PLC IP>:4840 → Read tag list from PLC.
  1. Properties ของ CPU → OPC UA → Server → General: ติ๊ก Activate OPC UA server และจด address ของ server (port 4840) และติ๊ก Enable standard server interface ด้วย (CPU ตระกูล 1200 firmware 4.5 ขึ้นไป และ CPU ตระกูล 1500 firmware 2.9 ขึ้นไป อยู่ใน Server interfaces) ถ้าไม่ติ๊ก PLC จะตอบแต่ไม่ส่ง tag ออกมา และหน้าต่าง PLC tags จะแจ้งเรื่องนี้
  2. Runtime licenses → OPC UA: เลือก OPC UA runtime licence ให้ตรงกับ CPU (small/medium/large สำหรับตระกูล 1500 หรือ Basic สำหรับตระกูล 1200)

Notes for developersหมายเหตุสำหรับนักพัฒนา

How the names get into PLC Monitor, for anyone extending it or connecting other tools:

กลไกการดึงชื่อเข้ามาใน PLC Monitor สำหรับผู้ที่จะพัฒนาต่อหรือเชื่อมกับเครื่องมืออื่น:

  • Why not over ISO-TCP? PUT/GET addresses memory as area + offset; symbols exist only in the engineering software project. Symbolic access on 1200/1500-series CPUs uses a newer proprietary protocol that is not open. OPC UA is the open, supported way to read by name.
  • Node IDs. The PLC's built-in server uses string node IDs that are the symbol itself, in its own namespace (usually ns=3): ns=3;s="Line_Data"."Motor"."Speed", ns=3;s="Start_PB". Always take the namespace from browsing, never hard-code it. The tree is Objects/<PLC name>/Inputs|Outputs|Memory|DataBlocksGlobal|DataBlocksInstance/….
  • Browsing (opcua.go, browseVars): breadth-first Browse from the Objects folder over hierarchical references (properties and namespace 0 skipped), then one Read per 100 variables for DataType, Description, AccessLevel and ValueRank. OPC UA built-in types map to tag types (Int16 → INT, Float → REAL, …); arrays and structures are listed but not offered as tags.
  • Monitoring by name. A tag with area: UA and node: …. All UA tags of a poll are read with one OPC UA Read per 100 nodes; a missing node marks only its own tag bad. Writes use the OPC UA type of the tag type (INT → Int16, REAL → Float, …).
  • No absolute addresses over OPC UA. To map a name to an absolute address (Read as: absolute address, Compare of ISO-TCP tags) the names imported in Scan PLC are used: DB sources are laid out with the standard access rules (symbols.go, layouter); tag tables give the address directly.
  • Files: imported names → plc-symbols.json; OPC UA client certificate → opcua-client-cert.pem / opcua-client-key.pem (application URI urn:plcmonitor:client), all next to the config.
  • API: POST /api/opcua/browse {"endpoint","security","username","password"}, GET /api/opcua/browse (progress and variables), POST /api/opcua/read {"nodes":[…]}, POST /api/opcua/tagfile (tags → YAML), /api/plcscan/symbols for imported names.
  • Without a PLC: the tests include a fake OPC UA server that behaves like a PLC's built-in server. Run it with $env:PLC_UA_SERVE="4840"; go test -run TestUAServe -timeout 0 and browse opc.tcp://127.0.0.1:4840. UaExpert is a good second opinion on what a real PLC publishes.
  • ทำไมไม่ดึงชื่อผ่าน ISO-TCP? PUT/GET อ้างตำแหน่งด้วย area + offset ส่วนชื่อ symbol มีอยู่แค่ในโปรเจกต์ของโปรแกรมเขียน PLC การเข้าถึงด้วยชื่อบน CPU ตระกูล 1200/1500 ใช้โปรโตคอลรุ่นใหม่ที่เป็นกรรมสิทธิ์และไม่เปิดเผย OPC UA จึงเป็นทางเปิดและรองรับอย่างเป็นทางการสำหรับการอ่านด้วยชื่อ
  • Node ID: server ที่ติดมากับ PLC ใช้ node ID แบบ string ที่เป็นชื่อ symbol เลย อยู่ใน namespace ของตัวเอง (ปกติ ns=3) เช่น ns=3;s="Line_Data"."Motor"."Speed", ns=3;s="Start_PB" ให้อ่านหมายเลข namespace จากการ browse เสมอ ห้าม fix ค่าไว้ โครงสร้างคือ Objects/<ชื่อ PLC>/Inputs|Outputs|Memory|DataBlocksGlobal|DataBlocksInstance/…
  • การ browse (opcua.go, browseVars): Browse แบบ breadth-first จาก Objects folder ตาม hierarchical reference (ข้าม property และ namespace 0) แล้ว Read ครั้งละ 100 ตัวแปร เพื่อเอา DataType, Description, AccessLevel และ ValueRank ชนิดข้อมูลพื้นฐานของ OPC UA แปลงเป็นชนิดของ Tag (Int16 → INT, Float → REAL, …) ส่วน array และ struct แสดงในรายการแต่เพิ่มเป็น Tag ไม่ได้
  • Monitor ตามชื่อ: Tag ที่มี area: UA และ node: … ทุก Tag แบบ UA ในแต่ละรอบอ่านด้วย OPC UA Read ครั้งละ 100 node ถ้า node ไหนหายไป จะเสียเฉพาะ Tag นั้น การเขียนใช้ชนิด OPC UA ตามชนิดของ Tag (INT → Int16, REAL → Float, …)
  • OPC UA ไม่ให้ absolute address: การแปลงชื่อเป็น absolute address (Read as: absolute address และ Compare ของ Tag แบบ ISO-TCP) ใช้ชื่อที่ import ใน Scan PLC โดย source ของ DB คำนวณตามกฎ standard access (symbols.go, layouter) ส่วน tag table ให้ address มาโดยตรง
  • ไฟล์: ชื่อที่ import → plc-symbols.json, certificate ของ OPC UA client → opcua-client-cert.pem / opcua-client-key.pem (application URI urn:plcmonitor:client) ทั้งหมดอยู่ข้างไฟล์ config
  • API: POST /api/opcua/browse {"endpoint","security","username","password"}, GET /api/opcua/browse (ความคืบหน้าและรายการตัวแปร), POST /api/opcua/read {"nodes":[…]}, POST /api/opcua/tagfile (Tag → YAML), /api/plcscan/symbols สำหรับชื่อที่ import
  • ทดสอบโดยไม่มี PLC: ในชุด test มี OPC UA server จำลองที่ทำงานเหมือน server ใน PLC สั่งรันด้วย $env:PLC_UA_SERVE="4840"; go test -run TestUAServe -timeout 0 แล้ว browse ที่ opc.tcp://127.0.0.1:4840 และใช้ UaExpert ตรวจดูว่า PLC จริงเปิดเผยอะไรบ้าง

MQTT Publish values with MQTTส่งค่าผ่าน MQTT

MQTT is a light publish/subscribe protocol. PLC Monitor publishes each change to a broker; any number of programs subscribe to the topics they need – HMIs, Node-RED, Home Assistant, phone apps, SCADA – without touching the PLC.

MQTT เป็นโปรโตคอลแบบ publish/subscribe ที่เบา PLC Monitor publish ทุกค่าที่เปลี่ยนไปที่ broker แล้วโปรแกรมอื่น ๆ จะ subscribe เฉพาะ topic ที่ต้องการกี่โปรแกรมก็ได้ เช่น HMI, Node-RED, Home Assistant, แอปมือถือ, SCADA โดยไม่ต้องเชื่อมต่อ PLC โดยตรง

Payload, chosen in Export → MQTT → Payload:

รูปแบบข้อมูล (payload) เลือกได้ที่ Export → MQTT → Payload:

JSON{"value":42.5,"quality":"good","address":"DB1.DBD4","type":"REAL","ts":"2026-11-19T10:15:00.123+07:00"}
Value onlyValue only (ค่าอย่างเดียว)42.5 · true · null (when the value is bad)(เมื่อค่าใช้ไม่ได้)

plcmonitor/status is online while PLC Monitor runs and becomes offline when it stops or loses the network (MQTT “last will”). Retain lets a new subscriber get the latest value immediately. QoS 1 is a good default.

plcmonitor/status เป็น online ขณะที่ PLC Monitor ทำงาน และเปลี่ยนเป็น offline เมื่อโปรแกรมหยุดหรือหลุดจาก network (ใช้ MQTT “last will”) ถ้าเปิด Retain ผู้ subscribe ที่เข้ามาใหม่จะได้ค่าล่าสุดทันที แนะนำให้ใช้ QoS 1 เป็นค่าเริ่มต้น

1. Install a broker (Mosquitto)1. ติดตั้ง broker (Mosquitto)

  1. Download the Windows installer from mosquitto.org and install it (it installs a Windows service).
  2. Mosquitto 2 only accepts connections from the same PC until you add a listener. Edit C:\Program Files\mosquitto\mosquitto.conf (as administrator):
  1. ดาวน์โหลดตัวติดตั้งสำหรับ Windows จาก mosquitto.org แล้วติดตั้ง (จะติดตั้งเป็น Windows service ให้อัตโนมัติ)
  2. Mosquitto 2 รับการเชื่อมต่อจากเครื่องตัวเองเท่านั้น จนกว่าจะเพิ่ม listener ให้แก้ไฟล์ C:\Program Files\mosquitto\mosquitto.conf (เปิดแบบ administrator):

allow_anonymous false

  1. Create a user, open the firewall and restart the service (PowerShell as administrator):
  1. สร้าง user เปิด firewall แล้ว restart service (PowerShell แบบ administrator):
cd "C:\Program Files\mosquitto"

2. Connect PLC Monitor2. ตั้งค่าใน PLC Monitor

  1. Open Export → MQTT and press a Quick setup button, or type the broker address. Just the IP (192.168.1.10) becomes tcp://192.168.1.10:1883.
  2. Username and password if the broker needs them. Leave the Client ID as plcmonitor unless several PLC Monitors use the same broker – each needs its own ID.
  3. Topic prefix (e.g. plant1/line2), payload, QoS and retain.

  3. ตั้ง topic prefix (เช่น plant1/line2), payload, QoS และ retain
  4. กด Test connection: โปรแกรมจะเชื่อมต่อด้วย ID ทดสอบแยกต่างหาก publish ไปที่ prefix/_test ตรวจว่าได้รับกลับมา และแสดงข้อความที่มีอยู่ใน broker ใต้ prefix/#
  5. ติ๊ก Publish values to an MQTT broker แล้วกด OK กล่อง MQTT ด้านบนจะแสดง OK เมื่อเชื่อมต่อสำเร็จ
export:
    mqtt:
        enabled: true
        broker: tcp://192.168.1.10:1883   # ssl://host:8883, ws://host:9001
        client_id: plcmonitor
        username: plcuser
        password: secret
        topic_prefix: plant1/line2
        qos: 1
        retain: true
        payload: json                     # json | value
